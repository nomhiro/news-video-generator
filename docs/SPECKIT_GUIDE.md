# Spec Kit 仕様駆動開発ガイド

## 📋 Spec-Driven Development とは

Spec-Driven Development（SDD）は、AIコーディングエージェントと協働するための開発手法です。
コードを先に書くのではなく、**仕様書（Spec）を最初に書き**、それを元にAIがコードを生成します。

```
従来: アイデア → コード → ドキュメント
SDD:  アイデア → 仕様書 → AIがコード生成 → 検証
```

---

## 🔄 4つのフェーズ

Spec Kitは以下の4フェーズで進行します：

```
┌─────────────────────────────────────────────────────────────────┐
│  Phase 1: CONSTITUTION (方針策定)                               │
│  ─────────────────────────────────────────────────────────────  │
│  プロジェクトの基本方針・開発ルールを定義                          │
│  → constitution.md                                              │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  Phase 2: SPECIFY (仕様策定)                                    │
│  ─────────────────────────────────────────────────────────────  │
│  機能要件・ユーザーストーリー・受け入れ基準を定義                   │
│  → spec.md                                                      │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  Phase 3: PLAN (計画策定)                                       │
│  ─────────────────────────────────────────────────────────────  │
│  技術スタック・アーキテクチャ・実装アプローチを定義                 │
│  → plan.md                                                      │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  Phase 4: TASKS (タスク分解)                                    │
│  ─────────────────────────────────────────────────────────────  │
│  実装タスクを小さく分解・順序付け                                  │
│  → tasks.md                                                     │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  Phase 5: IMPLEMENT (実装)                                      │
│  ─────────────────────────────────────────────────────────────  │
│  タスクを順番に実装・検証                                         │
│  → ソースコード                                                  │
└─────────────────────────────────────────────────────────────────┘
```

## 🚀 セットアップ手順

### 1. Spec Kit のインストール

```bash
# uvを使用（推奨）
uvx --from git+https://github.com/github/spec-kit.git specify init news-video-generator --ai claude

# または既存ディレクトリで初期化
cd news-video-generator
uvx --from git+https://github.com/github/spec-kit.git specify init . --ai claude
```

### 2. プロジェクト構造の確認

初期化後、以下の構造が作成されます：

```
news-video-generator/
├── .speckit/                    # Spec Kit設定
│   ├── prompts/                 # AIプロンプトテンプレート
│   └── config.yaml
├── specs/                       # 仕様ドキュメント
│   ├── constitution.md          # プロジェクト方針
│   ├── spec.md                  # 機能仕様
│   ├── plan.md                  # 技術計画
│   └── tasks.md                 # タスク一覧
└── src/                         # ソースコード（実装後）
```

## 📝 実行手順

### Step 1: Claude Codeを起動

```bash
cd news-video-generator
claude
```

### Step 2: Constitutionを作成

Claude Codeで以下のコマンドを実行：

```
/speckit.constitution
```

AIが質問してくるので、以下のように回答：

- **プロジェクトの目的**: ニュースから自動的にショート動画を生成するシステム
- **技術スタック**: Python, Claude API, ElevenLabs, fal.ai, FFmpeg
- **コード品質**: タイプヒント必須、docstring必須、エラーハンドリング重視
- **テスト**: ユニットテスト必須（pytest）

### Step 3: Specificationを作成

```
/speckit.specify
```

AIに以下を伝える：

```
このプロジェクトは、ニューストピックを入力として受け取り、
YouTube Shorts / TikTok向けのショート動画を自動生成するPythonアプリケーションです。

主な機能：
1. Claude APIでニュースから動画用台本を生成
2. ElevenLabs APIでナレーション音声を生成
3. fal.ai (Flux)でシーン画像を生成
4. FFmpegで音声+画像を動画に合成
5. 日本語版と英語版の両方を出力

詳細な仕様は specs/REQUIREMENTS.md と specs/SPECIFICATION.md を参照してください。
```

### Step 4: Clarification（任意）

仕様に不明点があれば：

```
/speckit.clarify
```

### Step 5: Planを作成

```
/speckit.plan
```

技術的な実装計画を生成します。

### Step 6: Tasksを作成

```
/speckit.tasks
```

実装タスクを分解します。

### Step 7: Implementを実行

```
/speckit.implement
```

タスクを順番に実装していきます。

## ⚠️ 重要なポイント

### 各フェーズで人間が確認すること

| フェーズ | 確認ポイント |
|---------|-------------|
| Constitution | 開発方針が適切か、制約条件が正しいか |
| Specify | 機能要件が網羅されているか、ユーザーストーリーが正確か |
| Plan | 技術選定が適切か、アーキテクチャに問題がないか |
| Tasks | タスク粒度が適切か、依存関係が正しいか |
| Implement | 生成されたコードが仕様を満たしているか |

### フェーズを進める前に

- **必ず生成されたドキュメントをレビュー**
- 問題があれば修正を指示
- 「LGTM」「進めてOK」と明示的に承認

## 📁 このプロジェクト用のドキュメント

以下のファイルをSpec Kitの `specs/` ディレクトリにコピーしてください：

| ファイル | 用途 |
|---------|------|
| `constitution.md` | プロジェクト方針（Spec Kit用に最適化済み） |
| `spec.md` | 機能仕様書（Spec Kit用に最適化済み） |
| `plan.md` | 技術計画書（Spec Kit用に最適化済み） |
| `tasks.md` | タスク一覧（Spec Kit用に最適化済み） |

これらのファイルは、手動で作成済みなので、Spec Kitの `/speckit.specify` 等を使わずに
直接 `/speckit.implement` から始めることもできます。
