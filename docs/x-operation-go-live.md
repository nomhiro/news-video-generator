実装は完了しているが、**まだ1件も投稿していない**。`X_POSTING_ENABLED` の既定は `false` で、
スイッチファイル（`data/x_posting.json`）も存在しない。

この文書は「有効にするまでに何を確かめるか」の作業リスト。上から順に進める。
設計の理由は `docs/superpowers/specs/2026-08-15-x-account-operation-design.md` と
`CLAUDE.md` にある。

## 1. X 側の準備（コードでは確認できない）

- [ ] X 開発者ポータルでアプリを作る（対象アカウント: `ri.innovate.shirokuma@gmail.com`）
- [ ] **従量課金の実単価を確認する。** 実装は「投稿 $0.015 / リンク付き投稿 $0.20 /
      読み取り $0.005」を前提にしているが、根拠は二次情報。違えば
      `X_COST_PER_POST_USD` / `X_COST_PER_POST_WITH_LINK_USD` を直す
- [ ] **weighted length の仕様を確認する。** CJK が2カウント・上限280（日本語140字）を

      （`X_REDIRECT_URI` の既定値。変えるなら両方揃える）
- [ ] **メディアアップロードのエンドポイントを確認する。** `src/social/x_client.py` の
      `UPLOAD_URL` は未検証のままコメントで明示してある。画像カードは毎日1件出るので、
      間違っているとその1件が毎日失敗する（画面の「失敗」に出る）


## 3. 下書き生成の疎通（2026-08-16 に確認済み）

- [x] `PostGenerator._complete` の `responses.parse`（Structured Outputs）が
      `gpt-5.1` デプロイで動く。**JSON モードに戻す必要はない。**
- [x] 実記事3本で下書きを生成し、3件とも予算内（weighted 239〜242 / 280）に
      収まることを確認した

このとき**下書きが1件も予算内に入らない不具合が見つかり、直した**（commit `7fb5e3a`）。
同じ記事で3回ずつ測った値:

| プロンプト | 生成された文字数 | 予算内（105〜125字） |
|---|---|---|
| 修正前（同じプロンプトを送り直す） | 70 / 80 / 70 | 0/3 |
| 構成の指示を足しただけ | 162 / 163 / 140 | 0/3 |
| 前回の字数と直す方向を伝える | 118 / 109 / 112 | 3/3 |

同じ入力なら同じ長さが返るので、引き直しても結果は変わらない。**投稿が毎回破棄されて
アカウントが沈黙する**状態だった。誤った投稿より気付きにくい壊れ方なので、
有効化前にここを通しておく価値は高い。

再確認したいときは記事を1本取ってきて `PostGenerator.generate` を呼び、
本文を読む（投稿はしない）。

## 切り戻しについて

**X 運用の導入より前のイメージには切り戻せない。** 記事 JSON に `consumed` を書くように
なったため、旧コードは `TypeError` で記事を読めなくなる。詳細と回避策は `CLAUDE.md` の
切り戻し手順の項。
